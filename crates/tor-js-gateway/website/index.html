Tor in the browser

Gateway server for tor-js — enabling real Tor circuits built locally in your browser using WebAssembly. All cryptography runs on your machine. The gateway never sees your traffic or knows your destination — it just relays encrypted bytes.

There is no DNS in KPS — the browser dials this address directly over WebRTC and pins the server by its certhash. Get it from a gateway operator (it's printed at gateway startup).

◈

KPS Transport

One UDP port, dialed by address — no CA, no domain. Browsers connect over WebRTC data channels; native clients over QUIC. Every request is one stream speaking strict HTTP/1.1.

 ⇆

TCP Relay via CONNECT

A CONNECT exchange turns a KPS stream into a raw byte pipe to a Tor relay. Your client builds circuits and negotiates keys — the gateway only forwards opaque, encrypted data.

Fast Bootstrap

All the directory data your client needs in a single brotli-compressed download. No multi-step directory protocol, no round trips to authorities — one fetch, decompressed in-page via WASM.

Connect to a Tor relay

Open a tunnel to any consensus relay. The browser dials the gateway's KPS address over WebRTC; the tunnel is a CONNECT exchange on one stream:

import { Gateway } from './torJsGateway.js'; // The KPS address pins the server: ip:port:certhash const gw = new Gateway('this-gateway-address'); // Open a relay tunnel (one KPS stream per tunnel) const sock = await gw.connect('198.51.100.1:9001'); // It's the KPS stream itself — read/write WHATWG streams (backpressured) const writer = sock.writable.getWriter(); await writer.write(new Uint8Array([0x16, 0x03, 0x01, ...])); const reader = sock.readable.getReader(); const { value } = await reader.read(); // Uint8Array from relay // More tunnels reuse the same KPS connection const sock2 = await gw.connect('203.0.113.5:443'); gw.close(); // close everything when done

Only addresses advertised in the current Tor consensus are allowed. The gateway rejects connections to non-relay or private IPs.

Bootstrap from a gateway

Download and parse the Tor consensus directly in the browser:

import { bootstrap } from './torJsGateway.js'; const { consensus, microdescs, authcerts } = await bootstrap( 'this-gateway-address', (ev) => console.log(ev.type), // optional progress callback ); console.log(`Got ${microdescs.length} relay descriptors`);

Run your own gateway
Install from source (requires Rust 1.89+):
cargo install --path . tor-js-gateway init # create config at ~/.config/tor-js-gateway/config.json5 tor-js-gateway # run in foreground tor-js-gateway install # or install as a systemd service
Manage the service with standard systemd commands:
systemctl --user status tor-js-gateway systemctl --user restart tor-js-gateway journalctl --user -u tor-js-gateway -f
